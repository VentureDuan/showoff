# 大规模实例 Agent 管理与状态收敛

状态：本轮口述已收敛，供后续网站编辑使用。

## 建议叙事与个人贡献

负责实例侧多 Agent 架构设计与代码实现。通过镜像内置的 CGInstanceAgent 管理服务生命周期、汇聚状态；适应 KVM 到无盘裸金属的基础设施变化，并面向约 20 万实例设计业务状态与心跳上报。

## Agent 职责

最新更正：CGInstanceAgent 是实例侧 Agent 服务，统一实例业务状态；对应云端 Union 服务名称为 CGInstanceMorintor。图与正文必须明确区分实例侧/云端，不用“CGInstanceAgent → Union”替代具体服务边界。名称按用户提供拼写保留。

| Agent | 职责 |
| --- | --- |
| CGInstanceAgent | 镜像内置服务；通过自更新升级自身；管理其他 Agent 的安装、卸载、更新，并汇聚状态 |
| CGVmAgent | 云游戏业务服务 |
| lightstreamer | 串流业务服务 |
| CGMetricsAgent | 运维服务，统一采集指标 |

保留用户给定名称，尤其 lightstreamer 不自行改变大小写。

## 部署链路

运维云端触发安装 → 下发 CGInstanceAgent → 执行安装 → CGInstanceAgent 收到对应 Agent 状态上报 → 判定部署成功。

不要将“安装命令执行完”直接等同于部署成功。所需状态的具体字段与判定规则未展开。

## 演进一：无盘实例与两级自更新

最初 Bundle 只需保证任务完成后，Agent 服务成功部署到实例。实例从 KVM 迁移到无盘裸金属后，重启会重置系统镜像，还原此前安装的 Agent 服务，因此增加 Bundle 自更新。

最终顺序：

1. Agent 自更新：先更新 CGInstanceAgent 自身。
2. Bundle 自更新：实例准备时，CGInstanceAgent bootload 对比云端数据库记录的目标版本与本地 Agent 版本，不一致则更新其他 Agent 程序，使版本一致。

不要把这两种更新合并成同一职责，也不要补写灰度、回滚、签名校验等未经介绍的能力。

## 演进二：约 20 万实例的状态汇聚

### 信号划分

- 心跳上报：CGInstanceAgent 健康状态、机器网络资源等。
- 业务上报：对应 Agent 是否能对外提供服务；其他 Agent → 实例侧 CGInstanceAgent → 云端 Union 服务 CGInstanceMorintor。
- 云端连续五个周期未收到实例心跳，将实例业务状态置为“已关机”。这是超时判定状态，不等同于物理断电证明。心跳周期具体秒数未提供。

### 方案取舍

最初 Union 收到业务状态后，与数据表记录比较，不一致才写表。

讨论过使用 Redis 缓存实例状态，供上报比较查询；经过容量与性能评估后认为不可靠，最终没有采用这一缓存方案。具体容量模型、基准数字未提供，不推论 Redis 普遍无法承载此规模。

最终把状态比较下放到实例 Agent：本地业务状态变化才启动上报，Union 收到业务状态后直接写表。降低重复业务上报与云端查询，减轻对公共中间件的依赖。不要误写为不再有心跳或不再依赖数据库。

### 收敛保障

- 业务状态变化后开启上报，直到上报成功；失败无限重试。
- 每隔 10 分钟触发兜底业务上报，使云端状态重新收敛。
- CGInstanceAgent 感知心跳上报失败时，也触发业务状态上报。
- 重试退避、抖动、乱序处理、状态版本号、重启时首次上报机制未介绍，不补写。
- Agent 感知的是本地心跳请求失败，不等同于已证明能够感知 Union 的所有超时判定。

## 展示边界

约 20 万实例是用户描述的需要承载的规模，没有独立吞吐测试结果；不换算未经证实的 QPS 或写成已验证的性能记录。

此案例聚焦实例侧服务管理与状态上报；云端实例锁、任务编排与调度互斥放在另一个案例，避免重复。
