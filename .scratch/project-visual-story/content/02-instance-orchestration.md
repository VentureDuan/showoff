# 实例任务编排与调度协同

状态：本轮口述已收敛，供后续网站编辑使用。

## 建议叙事

在 SaaS 与 IaaS 之间承接业务约束，协调用户占用、后台任务与资源操作；以实例锁、同步下调度、持久化任务和配置化失败策略，让批量任务在满足执行条件后推进。

## 业务问题

- 运营通过前端筛选一批机器，提交退订等任务。
- IaaS 需要退订机器，但用户仍在使用时必须等待退出；需要屏蔽跨层业务知识。
- 用户占用中不执行任务；任务执行中不允许机器被外放调度。
- 职责包括实例任务批处理、实例状态机管理、云端实例状态管理、实例锁、实例信息管理。

## 个人贡献与协作

用户主导系统设计与实现。部分 worker 执行逻辑、IaaS 接口封装由同事完成。

不能写为全部模块独立完成；各子模块具体代码占比未确认。

## 领域分工

- CGInstance：实例领域，判断实例状态及项目保留数，管理实例锁与任务推进。
- 调度领域：维护用户占用状态，向实例领域同步；控制实例是否接受新分配。
- 批处理执行 worker：无状态执行，所有执行数据保存在数据库表中。
- “项目保留数”的具体算法尚未展开，不补写实现。

## 主流程（采用用户最后更正的版本）

1. 请求 CGInstance，判断实例状态和项目保留数，抢实例锁。
2. 同步请求调度领域下调度。
3. 确认禁止新分配，并处理已有分配、会话；存在用户占用时等待退出。
4. 执行后台任务。
5. 确认任务结束、实例可用。
6. 对需要继续服务的实例恢复调度、释放实例锁，锁由 CGInstance 释放。

用户最初说“发布上下调度事件”，随后明确更正下调度为同步请求；后续不得重新采用异步事件消费作为主流程。恢复调度的具体接口方式未单独确认。

用户早先还说明任务后由 CGInstance 调用巡检工具，正常才恢复调度；最后流程概括为确认实例可用。可保留巡检作为已口述的检查方式，不自行添加具体检查项。

退订成功资源不应画回服务池；这是任务类型的展示边界，不表示已确认了具体终止分支代码。

## 等待与批量推进

用户退出后，调度感知退出并同步实例领域，修改占用状态。实例领域定时搜索“未占用且存在待执行任务”的机器，搜索后进行批处理。

## 失败与重启恢复

- 锁实例、下调度、后台任务等都是 activity。
- activity 失败按配置策略处理，包括自动重试、保持锁定等待处理。
- worker 无状态，所有数据保存在数据库表；worker 重启后可重新执行。
- CGInstance 统一负责实例锁释放。

不要把“可重新执行”升级为已证明的无副作用恢复、恰好一次或自动解锁。重试间隔、次数、幂等机制、超时、数据库领取并发控制均未展开。

## 重点工程判断

- 接收任务与满足条件后执行分离。
- 实例锁协调操作冲突，调度协同隔离新分配。
- 等待与执行进度持久化，使任务不绑定单个 worker 进程生命周期。
- 完成任务与恢复业务可用分开判断。
