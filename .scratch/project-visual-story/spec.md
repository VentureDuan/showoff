# 项目视觉叙事

## 目标

把简历式项目文字转为适合个人网站的视觉案例，通过图标、流程和可控动画解释问题、职责、方案与取舍。根据用户讨论，原云游戏后台系统拆为三个案例，与两个 AI 项目共五项；先确定内容，再进行视觉和动画设计。

## 设计方向（用户已确认）

- 模式：Redesign · Preserve；重组项目展示，保留全站身份。
- 受众：希望快速了解工程能力、再深入技术决策的访问者。
- 视觉语言：暖色工程手记；先读图，再读案例。
- 五个尺度：构图变化 5/10、动效 5/10、信息密度 5/10、素材依赖 2/10、品牌保留 9/10。流程图承担叙事，采用现有配色与字体，无需真实内部截图。
- 配色：背景 `#f7f7f2`、卡片 `#fff`、正文 `#252520`、次级 `#71716a`、线条 `#e7e7df`、强调 `#ffb629`、强调正文 `#b84a08`；使用现有 CSS 变量兼容深色主题。
- 字体：沿用 Microsoft YaHei UI / PingFang SC，技术标签 Consolas。正文 16–18px，标题 32–48px，图中文字不依赖悬停显示。
- 间距：8px 基础，16/24/32/48/64px 层级；卡片圆角 24px，内部节点 12px，沿用现有轻阴影。
- 动画：200–300ms 状态反馈；分步播放用短序列表达因果，可暂停与重播，遵循 prefers-reduced-motion。不是实时生产数据。
- 手机：流程转为纵向；点击与键盘均可查看步骤，静态内容可独立阅读。

## 内容与交互

### Ask-Venture Plugin

问题输入 → Gateway 检查目标、环境与现象 → 按领域加载 Skills → MCP 取证 → Markdown 研发交接。点击步骤显示其职责。用已披露的 LS 成功但 SDK launch 超时案例解释证据如何串联；不展示内部地址或原始日志。

### 云游戏启动性能分析 Agent

参数化查询 / 固定 SQL 与 Python → 确定性计算 → LLM 选择下钻与解释 → 调查报告 → Webhook。突出计算与解释职责，通过步骤演示展示循环下钻。无数值样本时不画虚构性能曲线。

### 云游戏后台系统（初始构想，已被内容缓存中的三案例方案替代）

用示意图展示集中管理、平台 Agent、业务 Agent 的职责。以准备、运行、维护作为讲解场景，点选切换职责说明。图表示工作范围，不声称还原内部部署拓扑或精确状态机。

## 页面组织

- 首页：代表项目增加有意义的视觉摘要与详情入口。
- 项目列表：按 Ask-Venture、启动性能分析 Agent、内容分发、实例任务编排、Agent 管理的确认顺序展示；专属图解见页面结构文档。
- 项目详情：问题 → 可探索的方案图 → 我的职责 / 关键取舍 → 结果与边界；保留现有事实与 URL。

## 交付与验证

先完成五项内容梳理，再确认设计方向，交付可查看的 v0 供校准；v0 确认后完善案例与动画。实现后运行项目 check / build，检查静态降级、键盘交互、深色主题规则与减少动态效果规则。除非另获授权，不部署或发布。
