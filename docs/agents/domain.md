# 领域文档

## 布局

采用 single-context：

- `GLOSSARY.md`：仓库统一术语表。
- `docs/adr/`：架构决策记录。

## 探索代码前

读取根目录 GLOSSARY.md，以及与当前工作相关的 ADR。

若未来存在 GLOSSARY-MAP.md，则按其索引读取相关上下文的术语表，
并检查对应的 src/<context>/docs/adr/。

这些文件不存在时直接继续，不主动建议补建。
domain-modeling 技能会在术语或决策确定后按需创建。

## 使用统一术语

任务标题、重构建议、假设和测试名称应使用术语表定义的词汇，
避免改用术语表明确排除的同义词。

缺少所需术语时，先判断是否引入了项目未使用的概念；
确有缺口则记录，供 domain-modeling 处理。

## 决策冲突

若建议与已有 ADR 冲突，明确指出对应 ADR 和重新讨论的理由，
不要静默覆盖已有决策。
